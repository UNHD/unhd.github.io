# 彼岸 / LYCORIS

石蒜主题的三维互动花庭，使用 TypeScript、Three.js 与 Vite。当前采用「夜间花庭」布局，以起伏的花海、宋体题签和底部章节刻度呈现四十份记录。

[进入夜间花庭](https://unhd.github.io/) · [打开青色代码标本](https://unhd.github.io/?specimen=LY-033&scene=detail)

馆藏包含五类各八份档案，可检索、收藏、导出，也可抽取标本并查看、拆解六组结构。网页直接加载 GLB，无需后端、Blender 或 API Key。

开场为约 17.6 秒的连续演出：九行 glitch 文本逐渐解码、错位并消隐，石蒜花标描线透红，居中的「彼岸」主题渐显定格，双层花海暗纹随后交叠淡入真实花海。Enter / Esc 或「进入花海」按钮可柔和跳过，页脚可以重播。

开场由主入口直接启动，主模型和花海首帧就绪后才继续揭幕；慢加载时保留主题与遮罩。远景简化模型在后台接入，不阻塞开场，加载失败时使用完整模型。页面隐藏时暂停开场，返回后继续；开启「减少动态效果」或使用指定场景的直达链接时直接进入花海。

花海保留连续循环、选中起伏、抽取跟随与转正归位；未选中花体呈灰色毛玻璃层次。选中时的局部图像后处理让花与周围画面弯曲、分色和横向错位，残像与数据碎片越出花的轮廓，红色侵染跟随花体；青色手记使用青色信号。选择、抽取和结构拆解时扰动增强，停留时缓缓回落。手记在抽取画面下方展开；观察室支持 360° 查看和六组拆解，展开时自动调整取景。标题、编号与章节细线分布轻微 glitch，开启「减少动态效果」可暂停动态故障与画面扭曲。

花海按相机视野与距离雾化范围生成连续阵列，适应宽屏和抽取镜头；标本完全出屏或融入远雾后才回收，实例与玻璃护罩通过对象池复用。雾化同时计算横向距离与前后深度，左右远处的花朵、玻璃、编号、地面及网格按同一规则平滑融入背景，画面中轴保留原有深度雾与近景细节，地面保留反光和网格。

信号统一自上而下：稀疏的纵向数据包穿过选中花朵并延伸到周围空间，局部丢帧、分色和错位残片随操作短暂出现，不再使用整条扫描线。血红侵染同样向下渗入，LY-033 使用青色信号。开场文字按从上到下的顺序解码、下落消隐；界面边缘有低亮度数据碎片，档案标题和切页出现短暂错位与渐显，石蒜暗纹中偶尔有局部花丝断裂。效果复用已有场景缓冲，暗纹使用矢量遮罩；轻量预览减少界面数据列，减少动态效果时停用数据流和故障动效，保留静态暗纹。页面动效选项优先于系统偏好。

「精细画质 · 自适应」在持续卡顿后逐级减轻负担，避免画质反复切换；关闭它可直接使用轻量预览，重新开启或刷新可重置预算。精细、均衡、轻量分别限制为 400、200、100 万绘制像素，正文和控件不受影响。精细保留四倍抗锯齿与 75% 折射缓冲；均衡使用两倍抗锯齿与 50% 折射缓冲；轻量保留两倍抗锯齿，使用深色磨砂透明玻璃替代实时折射，并更早切换远景简化几何。选中及附近的花形保持完整，地面反光、网格和雾化保留，画质调整不会复位观察室镜头。场景离开视口、开场完全遮盖场景或减少动态效果下静止时暂停重复绘制。

## 本地开发

需要 Node.js 24 或更新版本。

```sh
npm ci
npm run dev
npm run build
npm run check
npm run preview
```

`npm run build` 先导出 40 份 TXT 档案，再执行 TypeScript 检查和 Vite 构建，结果位于 `dist/`。

`npm run check` 包含 38 项档案、模型、动画、渲染优化与开场加载顺序检查，覆盖宽屏阵列连续性、自适应降档、轻量材质切换与后处理缓冲释放。修改 GLSL 或花体后处理时，在 Windows 上另行运行 `npm run check:shaders`。

四十份标本各有独立的诗意文案。手动修改时，在 `src/lycoris/archive-copy.ts` 中按编号编辑 `summary`、三段 `paragraphs` 与 `tags`；名称及英文标题位于 `src/lycoris/data.ts`。运行 `npm run build` 会同步生成 `public/archives/` 中的 TXT，无需逐份修改导出文件。

矢量花形已包含在源码中；需要重新导出时，可使用 Python 运行 `scripts/export-opening-flower.py` 生成暗纹花形，加 `--emblem` 参数导出石蒜花标与网站图标。两者使用建模时的花形参数与随机种子，网页运行不依赖 Python。

## 发布

仓库 Settings → Pages → Source 使用 **Deploy from a branch**，选择 **main /docs**。`main` 保存网页源码与 `docs/` 中的生产构建；`gh-pages` 保留旧版，不再更新。

更新时运行 `npm run build` 和 `npm run check`，用本次 `dist/` 的内容完整替换 `docs/`（移除过期的带哈希资源），把源码与 `docs/` 一起提交并推送到 `main`。GitHub Pages 随后自动发布。`public/.nojekyll` 随构建复制到 `docs/`，避免 Jekyll 处理静态文件。网站基础路径仍为 `/`，不是 `/docs/`；仅改源码而未更新 `docs/` 不会改变线上页面。

当前账号凭据没有新增 Actions 工作流所需的 `workflow` 权限，因此采用分支发布，不依赖额外授权。
